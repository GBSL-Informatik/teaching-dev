# CMS

:::warning[WIP]
Das CMS ist aktuell noch in der Entwicklungsphase und kann noch Fehler oder Unvollständigkeiten enthalten.
:::

## Konzept

Das CMS ist im Package __packages/hfr/github-cms__ umgesetzt. Der visuelle Editor basiert auf [ProseMirror](https://prosemirror.net/), der Zustand wird mit MobX verwaltet. Die Anbindung an Github wird mit dem offiziellen [Octokit](https://github.com/octokit) vorgenommen, wobei für die Github-Anmeldung und die Zugriffstoken für Repositories die [Teaching-Dev API](https://github.com/GBSL-Informatik/teaching-api/pull/30) verwendet wird.

Dies ermöglicht es, dass direkt aus dem CMS heraus Änderungen an den Markdown-Dateien vorgenommen werden können. Da Octokit die Limitation mitbringt, dass nur eine Datei auf einmal bearbeitet werden kann, lassen sich übers CMS auch Branches erstellen und Pull-Requests erstellen - und Bonus: auch Mergen 🥳.

### Bilder und Assets
Bilder können direkt über einen Bild-Dialog eingefügt, hochgeladen und verändert werden. Beim Upload werden dabei Bilder stets in den Ordner `images` des bearbeiteten Dokuments abgelegt.

:::cards
Vor dem Bild-Upload
```
docs
└── app-architecture
    └── cms
        └── index.mdx
```
::br
Nach dem Bild-Upload
```
docs
└── app-architecture
    └── cms
        ├── images
        │   └── hochgeladen.jpg
        └── index.mdx
```
:::

Assets (alles andere, auch Videos, PDF's etc.) werden standardmässig in den Ordner `assets` abgelegt.

:::cards
Vor dem PDF-Upload
```
docs
└── app-architecture
    └── cms
        └── index.mdx
```
::br
Nach dem PDF-Upload
```
docs
└── app-architecture
    └── cms
        ├── assets
        │   └── hochgeladen.pdf
        └── index.mdx
```
:::

:::danger[Gelöschte Bilder und Assets]
Bilder können ohne überprüfung, ob sie noch in einem Dokument verwendet werden, gelöscht werden. Erst beim Builden der Seite wird dies bemerkt, was je nach Einstelung zu einem fehlerhaften Build führen kann.
:::


### Editor

Der Editor liegt im Ordner __packages/hfr/github-cms/editor__:

`markdown/`
: Wandelt MDX in ein ProseMirror-Dokument um und zurück. Geparst wird mit `mdast-util-from-markdown` und denselben Syntax-Erweiterungen wie in Teaching-Dev (MDX, GFM, Direktiven, Mathematik, Frontmatter).
: Unveränderte Knoten werden mit ihrem ursprünglichen Markdown geschrieben. Wird eine Datei ohne Änderungen gespeichert, entsteht kein Diff, und eine Änderung betrifft nur die bearbeiteten Zeilen.
`schema/`
: Das ProseMirror-Schema. Verschachtelte Komponenten (Admonitions, Details, JSX-Elemente) sind normale Knoten mit Block-Inhalt. Das ganze Dokument wird in einem einzigen Editor mit einer Auswahl und einem Undo-Verlauf bearbeitet.
: Was der Editor nicht darstellen kann (z.B. `import`-Anweisungen oder `{Ausdrücke}`), bleibt als Quelltext erhalten und kann direkt bearbeitet werden.
`models/MdxDocument.ts`
: Hält den ProseMirror-Zustand als MobX-Observable. Toolbar und Node-Views beobachten den Zustand, Änderungen werden verzögert als Markdown in die Datei geschrieben.
`nodeViews/`
: React-Komponenten für Knoten wie Direktiven, JSX-Elemente, Bilder oder Mathematik. Code-Blöcke werden mit CodeMirror bearbeitet, Mermaid-Diagramme neben ihrer Vorschau.
: Bildunterschriften werden als Text (Markdown) unter dem Bild bearbeitet, die Bild-Optionen wie `--width=20em` separat in den Bild-Einstellungen. Beides wird im Alt-Text gespeichert.
`plugins/`
: ProseMirror-Plugins: Tastenkürzel, Markdown-Kürzel, Ziehgriff für Blöcke, Definitionslisten und UUID-Markierungen.
`SourceEditor/`
: Bearbeitet den Quelltext einer Datei mit CodeMirror, z.B. für `.ts`-Dateien oder wenn der visuelle Editor ausgeschaltet ist.
`components/MdxDiff/`
: Zeigt die Änderungen seit dem letzten Speichern (nebeneinander oder untereinander). Einzelne Änderungen können rückgängig gemacht werden, der visuelle Editor lädt die Datei danach neu.

Kann eine Datei nicht als MDX geparst werden, wird sie im Quelltext-Editor geöffnet.

#### Neue Syntax unterstützen

1. Knoten oder Markierung im Schema (`schema/index.ts`) ergänzen.
2. Die Umwandlung in `markdown/parse.ts` und `markdown/serialize.ts` ergänzen.
3. Optional eine Node-View in `nodeViews/` hinzufügen und in `nodeViews/index.ts` registrieren.

Die Tests in __editor/markdown/tests__ prüfen unter anderem, dass alle Markdown-Dateien dieses Repositories unverändert bleiben, wenn sie geöffnet und wieder gespeichert werden.

## Installation

```ts title="docusaurus.config.ts"
import dynamicRouterPlugin, { Config as DynamicRouteConfig} from './src/plugins/plugin-dynamic-routes';

const config: Config = {
    presets: [
        [
            'classic',
            {
                docs: {
                    editUrl: '/cms/',
                },
                blog: {
                    editUrl: '/cms/',
                },
                pages: {
                    editUrl: '/cms/',
                },
            }
        ]
    ],
    themeConfig: {
        navbar: {
            items: [
                {
                    to: '/cms',
                    label: 'CMS',
                    position: 'left',
                }
            ]
        }
    },
    plugins: [
        [
            dynamicRouterPlugin,
            {
                routes: [
                    {
                        path: '/rooms/',
                        component: '@tdev-components/Rooms',
                    },
                    {
                        path: '/cms/',
                        component: '@tdev-components/Cms',
                    }
                ]
            } satisfies DynamicRouteConfig
        ],
    ]
};
```

Die Abhängigkeiten sind in __packages/hfr/github-cms/package.json__ festgelegt und werden mit `yarn install` installiert.
