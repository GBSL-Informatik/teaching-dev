```py live_pyo id=62007a34-9647-4c62-83bd-7a0f829e502a title=Cookie_Klicker
from random import randint
from cookie_klicker import use_cookie
from webio import on_click, on_event, on_key, run

cookie = use_cookie('cookie')
zweiter_cookie = use_cookie('cookie-zwei')
klicks = 0

@on_event(source=[cookie.events, zweiter_cookie.events])
def log(event):
    print(event)

@on_click(cookie)
def drehen(event):
    global klicks
    klicks += 1
    cookie.set_rotation(cookie.rotation + randint(0, 360))
    if klicks % 3 == 0:
        hue = randint(0, 359)
        saturation = randint(50, 100)
        lightness = randint(35, 65)
        cookie.set_color(f'hsl({hue}, {saturation}%, {lightness}%)')

@on_click(zweiter_cookie)
def schrittweise_drehen(event):
    zweiter_cookie.set_rotation(zweiter_cookie.rotation + 30)

@on_key(zweiter_cookie, 'ArrowLeft')
def nach_links_drehen(event):
    zweiter_cookie.set_rotation(zweiter_cookie.rotation - 5)

@on_key(zweiter_cookie, 'ArrowRight')
def nach_rechts_drehen(event):
    zweiter_cookie.set_rotation(zweiter_cookie.rotation + 5)

await run()
```
</CodeShowcase>

## Ereignisse verarbeiten

Die Decorators aus `webio` funktionieren mit allen Erweiterungs-Handles, die eine Ereignisquelle als `events` bereitstellen.

`@on_click(target)`
: Registriert einen Klick-Handler; entspricht `@on_event('click', source=target.events)`.
`@on_key(target, key=None)`
: Registriert einen Tastatur-Handler. Ein Tastenname wie `'ArrowLeft'` filtert die Ereignisse; `None` und `'*'` empfangen alle Tasten. Der Tastenname steht in `event.payload['key']`.
`@on_event(event_type=None, *, source)`
: Registriert einen Handler für eine Quelle oder eine Liste von Quellen. `source` ist erforderlich und muss als benanntes Argument übergeben werden. Ohne Ereignistyp sowie mit `None` oder `'*'` werden alle Ereignistypen empfangen.
`await run()`
: Startet den Empfang nach der Registrierung der Handler und hält das Programm aktiv. Pro Ausführung ist nur ein Aufruf erlaubt.
`webio.stop()`
: Beendet den Empfang nach dem aktuellen Handler. Alternativ beendet **Abbrechen** im Editor die Ausführung sofort.

Jeder Handler erhält ein Ereignis mit folgenden Attributen:

`type`
: Ereignistyp, etwa `'click'` oder `'key'`.
`extension`
: Name der Erweiterung, hier `'cookie_klicker'`.
`target_id`
: ID der auslösenden Komponente.
`timestamp`
: Zeitpunkt des Ereignisses in Millisekunden seit der Unix-Epoche.
`payload`
: Ereignisspezifische Daten; beim Cookie `None` für Klicks und `{'key': ...}` für Tastatureingaben.

## Cookies steuern

`cookieId`
: Verbindet die React-Komponente mit `use_cookie(id)`. Mehrere Ansichten derselben ID teilen ihren Zustand.
`use_cookie(id)`
: Liefert innerhalb derselben Ausführung denselben Handle zurück. Ein neuer Handle verändert die bisherige Anzeige erst mit seinem ersten Update.
`events`
: Ereignisquelle des Handles für `@on_event`.
`rotation`
: Lokaler Winkel des Handles in Grad, anfangs `0`. Er liest den Browser-Zustand nicht zurück.
`set_rotation(winkel)`
: Normalisiert den Winkel auf `[0, 360)` und aktualisiert die Anzeige.
`color`
: Lokale Farbe des Handles, anfangs `'var(--ifm-color-warning-light)'`.
`set_color(css_farbe)`
: Aktualisiert die Farbe, etwa mit `'#ff8800'` oder `'hsl(120, 70%, 50%)'`.

## Ablauf und Grenzen

Eine Ereignisquelle kann gleichzeitig nur von einem laufenden Programm abonniert werden. Ein zweites Programm erhält eine Fehlermeldung. Nach Ende oder Abbruch werden die Abonnements entfernt; alte Ereignisse werden nicht an einen Neustart weitergegeben.

Handler laufen nacheinander. Für absichtliche Wartezeiten kann ein Handler `async def` verwenden und `await asyncio.sleep(0.1)` aufrufen. Währenddessen können weitere Klicks empfangen werden; ihre Handler starten nach Abschluss des aktuellen Handlers. `time.sleep()`, synchrone Eingaben mit `input()` und lange Berechnungen blockieren dagegen den Empfang im Worker.

Fehler in Handlern und überfüllte Ereigniswarteschlangen beenden die betroffene Ausführung mit einer Fehlermeldung.

## Auf der eigenen Website einrichten

Voraussetzung ist das [installierte Pyodide-Package](./README.mdx#installation).

<Steps>

1. Kopiere den vollständigen Ordner [cookie-klicker](https://github.com/GBSL-Informatik/teaching-dev/tree/main/tdev-website/website/pyodide/cookie-klicker) nach __website/pyodide/cookie-klicker__. Er enthält Komponenten, Styles, Browser-Store und Python-Modul.
2. Ergänze den Ordner in der bestehenden `extensions`-Liste des [Pyodide-Plugins](./README.mdx#erweiterungen-registrieren):

    ```ts title="siteConfig.ts"
    extensions: [
        './website/pyodide/cookie-klicker'
    ]
    ```

3. Starte den Entwicklungsserver neu. Danach kannst du die MDX-Beispiele oben verwenden.

</Steps>

Die __extension.json__ im kopierten Ordner legt den Namen und die Einstiegspunkte fest. Der Browser-Store wird automatisch initialisiert; der `SiteStore` deiner Website benötigt keine Ergänzungen.
