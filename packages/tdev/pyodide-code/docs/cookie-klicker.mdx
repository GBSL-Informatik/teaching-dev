# Cookie-Klicker: Browser-Ereignisse in Python

`@on_click(target)` ist ein generischer Decorator für Erweiterungs-Handles, die ihre Ereignisquelle als `events` bereitstellen. Er kann beispielsweise mit einem Button, einem anderen interaktiven Objekt oder mit `@on_click(cookie)` für den folgenden Cookie verwendet werden. Dafür sind weder eine gemeinsame Basisklasse noch Cookie-spezifische Funktionen in `webio` nötig. Der Handler erhält ein Ereignis mit `type`, `extension`, `target_id`, `timestamp` und `payload`. `await run()` hält das Programm aktiv, bis `webio.stop()` aufgerufen oder im Editor **Abbrechen** gedrückt wird.

Der Store verwaltet für jede `cookieId` ein eigenes MobX-Modell. Mehrere Cookies können unabhängig gesteuert werden; mehrere Ansichten derselben ID teilen dasselbe Modell.

```py live_pyo id=62007a34-9647-4c62-83bd-7a0f829e502a title=Cookie_Klicker
from random import randint
from cookie_klicker import use_cookie
from webio import on_click, on_event, on_key, run

cookie = use_cookie('cookie-demo')
zweiter_cookie = use_cookie('cookie-zwei')
klicks = 0

@on_event(source=[cookie.events, zweiter_cookie.events])
def protokollieren(event):
    print(f'{event.target_id}: {event.type}, payload={event.payload}')

@on_click(cookie)
def drehen(event):
    global klicks
    klicks += 1
    cookie.set_rotation(cookie.rotation + randint(0, 360))
    if klicks % 3 == 0:
        hue = randint(0, 359)
        saturation = randint(50, 100)
        lightness = randint(35, 65)
        cookie.set_color(f'hsl({hue}, {saturation}%, {lightness}%)')

@on_click(zweiter_cookie)
def schrittweise_drehen(event):
    zweiter_cookie.set_rotation(zweiter_cookie.rotation + 30)

@on_key(zweiter_cookie, 'ArrowLeft')
def nach_links_drehen(event):
    zweiter_cookie.set_rotation(zweiter_cookie.rotation - 5)

@on_key(zweiter_cookie, 'ArrowRight')
def nach_rechts_drehen(event):
    zweiter_cookie.set_rotation(zweiter_cookie.rotation + 5)

await run()
```

Der gemeinsame Logger gibt jedes Ereignis beider Cookies im Editor aus, einschliesslich Tasten ohne eigene Spielaktion. `@on_event(source=[cookie.events, zweiter_cookie.events])` empfängt alle Ereignistypen der angegebenen Quellen. Der optionale Ereignistyp ist standardmässig `None`; explizites `None` oder `'*'` haben dieselbe Bedeutung. `source` akzeptiert weiterhin auch eine einzelne Quelle; mit einem konkreten Ereignistyp wie `'click'` werden nur passende Ereignisse zugestellt.

Der Cookie wird anklickbar, sobald das Programm seine Ereignisquellen angemeldet hat. Eine Ziel-ID kann gleichzeitig nur von einem laufenden Programm für Ereignisse verwendet werden. Ein zweiter Controller erhält eine Fehlermeldung. Nach Ende oder Abbruch werden die Zuordnungen entfernt; alte Klicks werden nicht an einen Neustart weitergegeben.

`@on_key(target)` registriert einen generischen Handler für alle Tasten. Dasselbe gilt mit `None` oder `'*'` als zweitem Parameter. Ein anderer Tastenname filtert die Ereignisse, zum Beispiel `@on_key(target, 'ArrowLeft')`. Der Cookie sendet bei `keydown` den Tastennamen als `event.payload['key']`. Tastatureingaben gehen nur an den fokussierten Cookie: Wähle den zweiten Cookie mit Tab oder einem Klick aus. Die Pfeiltasten Links und Rechts drehen ihn jeweils um 5°; dabei wird das Scrollen der Seite verhindert. Enter und die Leertaste behalten ihre normale Button-Funktion.

`use_cookie(id)` liefert innerhalb derselben Ausführung denselben Handle zurück. Seine lokale `rotation` beginnt bei null; `set_rotation()` normalisiert den Winkel auf `[0, 360)` und aktualisiert das Browser-Modell. `set_color(css_farbe)` ändert die Farbe des Cookies, beispielsweise mit `'hsl(120, 70%, 50%)'` oder `'#ff8800'`. Der erste Cookie erhält bei jedem dritten Klick eine zufällige HSL-Farbe. Rotation und Farbe können unabhängig voneinander aktualisiert werden. Ein neuer Handle verändert die bisherige Anzeige erst mit seinem ersten Update.

Handler laufen nacheinander. Für absichtliche Wartezeiten kann ein Handler `async def` verwenden und `await asyncio.sleep(0.1)` aufrufen. Währenddessen können weitere Klicks empfangen werden; ihre Handler starten nach Abschluss des aktuellen Handlers. `time.sleep()`, synchrone Eingaben mit `input()` und lange Berechnungen blockieren dagegen den Empfang im Worker.

Für weitere Ereignistypen steht `@on_event('typ', source=cookie.events)` zur Verfügung. `webio.stop()` beendet den Empfang nach dem aktuellen Handler. Pro Ausführung ist ein `run()`-Aufruf vorgesehen; bei einem Handler-Fehler wird das Programm mit einer Diagnose beendet. Überfüllte Ereigniswarteschlangen beenden die betroffene Ausführung ebenfalls mit einer Fehlermeldung.
