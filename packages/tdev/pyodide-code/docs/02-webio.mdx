# webio: Ereignisse verarbeiten

Mit `webio` verarbeitet Python Browser-Ereignisse von Erweiterungen. Das Modul gehört zum Pyodide-Package. Ein vollständiges Beispiel mit Klicks und Tastatureingaben zeigt der [Cookie-Klicker](./04-cookie-klicker.mdx).

## Handler registrieren

Die Decorators aus `webio` funktionieren mit allen Erweiterungs-Handles, die eine Ereignisquelle als `events` bereitstellen.

`@on_click(target)`
: Registriert einen Klick-Handler; entspricht `@on_event('click', source=target.events)`.
`@on_key(target, key=None)`
: Registriert einen Tastatur-Handler. Ein Tastenname wie `'ArrowLeft'` filtert die Ereignisse; `None` und `'*'` empfangen alle Tasten. Der Tastenname steht in `event.payload['key']`.
`@on_event(event_type=None, *, source)`
: Registriert einen Handler für eine Quelle oder eine Liste von Quellen. `source` ist erforderlich und muss als benanntes Argument übergeben werden. Ohne Ereignistyp sowie mit `None` oder `'*'` werden alle Ereignistypen empfangen.

## Empfang starten und beenden

`await run()`
: Startet den Empfang nach der Registrierung der Handler und hält das Programm aktiv. Pro Ausführung ist nur ein Aufruf erlaubt.
`webio.stop()`
: Beendet den Empfang nach dem aktuellen Handler. Alternativ beendet **Abbrechen** im Editor die Ausführung sofort.

## Ereignisattribute

Jeder Handler erhält ein Ereignis mit folgenden Attributen:

`type`
: Ereignistyp, etwa `'click'` oder `'key'`.
`extension`
: Konfigurierter Name der Erweiterung, beispielsweise `'cookie_klicker'`.
`target_id`
: Ziel-ID der Ereignisquelle.
`timestamp`
: Zeitpunkt des Ereignisses in Millisekunden seit der Unix-Epoche.
`payload`
: Ereignisspezifische Daten der Erweiterung; beim Cookie `None` für Klicks und `{'key': ...}` für Tastatureingaben.

## Ablauf und Grenzen

Eine Ereignisquelle kann gleichzeitig nur von einem laufenden Programm abonniert werden. Ein zweites Programm erhält eine Fehlermeldung. Nach Ende oder Abbruch werden die Abonnements entfernt; alte Ereignisse werden nicht an einen Neustart weitergegeben.

Handler laufen nacheinander. Für absichtliche Wartezeiten kann ein Handler `async def` verwenden und `await asyncio.sleep(0.1)` aufrufen. Währenddessen können weitere Ereignisse empfangen werden; ihre Handler starten nach Abschluss des aktuellen Handlers. `time.sleep()`, synchrone Eingaben mit `input()` und lange Berechnungen blockieren dagegen den Empfang im Worker.

Fehler in Handlern und überfüllte Ereigniswarteschlangen beenden die betroffene Ausführung mit einer Fehlermeldung.
